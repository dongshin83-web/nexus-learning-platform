HyperMesh Workflow Map

HyperMesh는 geometry를 예쁘게 정리하는 도구가 아니라 solver가 해석 가능한 구조를 만드는 전처리 환경입니다. 각 단계의 결과가 `.inp` deck과 Abaqus 결과 신뢰도에 직접 반영됩니다.

1. CAD Import

형상 수입과 단위계

CAD가 들어오는 순간 단위, 좌표계, part 분할, 작은 feature의 의미가 결정됩니다.

  • 확인 기준: mm-tonne-MPa 계열인지, m-kg-Pa 계열인지 명확한가?
  • 좌표계와 하중 방향이 Abaqus 결과 component와 일관적인가?
  • 불필요한 작은 edge가 mesh seed를 과도하게 지배하지 않는가?
2. Topology Cleanup

연결성 정리

free edge, duplicate surface, gap, overlap은 solver 단계에서 contact 누락이나 local stiffness 오류로 나타납니다.

  • free edge가 의도한 경계인지, geometry 결함인지 분리합니다.
  • shared topology가 필요한 부위와 contact surface로 남겨야 할 부위를 구분합니다.
  • cleanup 기록에는 삭제한 feature와 삭제 이유를 남깁니다.
3. Idealization

midsurface와 element 차원

shell, solid, beam 선택은 mesh 편의가 아니라 물리 현상 표현 방식의 선택입니다.

  • thin wall은 midsurface와 thickness/orientation이 핵심 evidence입니다.
  • local bearing, fillet stress, contact pressure가 중요하면 solid 유지가 필요할 수 있습니다.
  • beam idealization은 joint stiffness와 offset 정의가 같이 확인되어야 합니다.
4. Mesh Strategy

mesh density와 transition

좋은 mesh는 균일한 mesh가 아니라 stress gradient와 load path를 읽을 수 있는 mesh입니다.

  • hole, notch, contact edge, load introduction 부위는 refinement 근거가 필요합니다.
  • coarse-to-fine transition이 stiffness jump를 만들지 않는지 확인합니다.
  • 결과 관심 부위와 mesh refinement 부위가 일치해야 합니다.
5. Connector

fastener, weld, RBE

connector는 실제 조립을 단순화한 모델입니다. 과도하게 강한 연결은 load path를 바꿉니다.

  • RBE2는 강체 연결, RBE3는 분산 연결로 읽습니다.
  • bolt preload, weld line, adhesive area는 force path와 함께 검토합니다.
  • connector failure를 볼 것인지, 주변 구조 stiffness만 볼 것인지 분리합니다.
6. Solver Export

Abaqus profile handoff

최종 기준은 HyperMesh 화면이 아니라 Abaqus input deck입니다. property, set, surface, contact, load 이름이 해석 의도를 담아야 합니다.

  • material/section/property 이름이 deck에서 추적 가능한가?
  • surface, elset, nset 이름이 contact와 output request에 연결되는가?
  • export 후 Abaqus datacheck 또는 input scan 기준을 둡니다.
Mesh Quality Metrics

mesh quality 숫자는 절대 합격/불합격표가 아니라 결과 리스크를 가리키는 계기판입니다. 어떤 metric이 어떤 물리 오해를 만들 수 있는지 연결해서 봅니다.

Shape

aspect, skew, angle

길쭉하거나 비틀린 element는 stress gradient와 local stiffness를 왜곡할 수 있습니다.

  • critical hot spot 주변 quality를 전체 평균보다 우선 확인합니다.
  • transition zone에서 skew가 몰리면 stiffness path를 의심합니다.
  • mesh quality plot과 stress contour를 나란히 봅니다.
Shell

warpage, normals, thickness

shell 모델은 두께와 법선 방향이 결과 해석의 출발점입니다.

  • normal direction이 pressure, contact, top/bottom stress 해석과 맞는지 봅니다.
  • midsurface offset이 assembly gap과 contact 조건을 바꾸지 않는지 확인합니다.
  • warpage가 큰 부위는 bending stress 해석이 흔들릴 수 있습니다.
Solid

jacobian, tet/hex quality

solid element는 volume distortion과 integration 안정성이 중요합니다.

  • Jacobian 저하는 distorted element와 negative volume risk를 뜻합니다.
  • first-order tet는 bending dominated 문제에서 stiffness가 과도해질 수 있습니다.
  • reduced integration solid는 hourglass 가능성을 Abaqus evidence와 함께 봅니다.
Connectivity

free edge, equivalence, duplicate

겉보기 mesh가 좋아도 connectivity가 잘못되면 구조물은 다른 물체가 됩니다.

  • equivalence가 필요한 node와 분리되어야 할 contact pair를 구분합니다.
  • duplicate element는 local stiffness와 mass를 동시에 바꿉니다.
  • free edge 리스트는 의도한 경계와 오류 후보로 분류합니다.
Abaqus Handoff Evidence

HyperMesh 작업이 끝났다는 기준은 mesh 화면이 아니라 Abaqus에서 읽을 수 있는 deck evidence입니다. 아래 항목은 handoff 전에 반드시 남겨야 합니다.

*Shell Section, elset=BRACKET_SHELL, material=AL6061
2.0
*Elset, elset=LOAD_ZONE
...
*Nset, nset=FIXTURE_BOLTS
...
*Surface, type=ELEMENT, name=CONTACT_PAD
PAD_ELSET, S3
*Connector Section, elset=BOLT_CONNECTORS
...
Deck Names

이름이 의도를 담는가

elset, nset, surface, property 이름은 검토 가능한 모델 문서입니다.

기준: 이름만 보고 fixture, load zone, contact pair, material group을 추적할 수 있어야 합니다.
Mesh Report

quality summary

전체 element count보다 관심 부위의 worst quality와 위치가 더 중요합니다.

기준: worst element를 숨기지 말고, 결과 관심 부위와 겹치는지 먼저 봅니다.
Assumption Log

삭제한 것과 남긴 것

geometry cleanup은 모델 가정을 바꾸는 작업입니다. 삭제한 feature와 이유가 남아야 재검토가 가능합니다.

주의: 작은 fillet 삭제가 전체 stiffness에는 작아도 local stress에는 클 수 있습니다.
Two-Week Work Plan
Day 1

HyperMesh model tree 읽기

component, property, material, set, surface 구조를 한 장으로 정리합니다.

Day 2

CAD import와 단위계 점검

좌표계, 단위, part 분할, small feature 후보를 표시합니다.

Day 3

Topology cleanup log 작성

free edge, gap, overlap, duplicate surface를 오류와 의도된 경계로 분류합니다.

Day 4

midsurface와 thickness 확인

shell 대상 부위의 midsurface offset, normal direction, thickness assignment를 검토합니다.

Day 5

mesh quality 기준표 만들기

aspect, skew, warpage, jacobian 기준을 부품군과 관심 결과별로 정리합니다.

Day 6

critical zone mesh refinement

hole, notch, contact edge, load introduction 부위의 mesh density 근거를 남깁니다.

Day 7

connector와 load path 점검

RBE, bolt, weld, adhesive 단순화가 구조 stiffness를 어떻게 바꾸는지 정리합니다.

Day 8

Abaqus solver profile export

export된 `.inp`에서 material, section, set, surface, contact 이름을 추적합니다.

Day 9

mesh sensitivity mini test

같은 geometry에서 coarse/medium/fine mesh를 비교하고 U, Mises, RF trend를 기록합니다.

Day 10

Handoff checklist 완성

HyperMesh 모델에서 Abaqus deck로 넘어갈 때 필요한 evidence 항목을 표준화합니다.

Deliverables
Deliverable 1

Geometry Cleanup Log

삭제/병합/수정한 feature와 그 이유를 기록합니다.

  • 삭제한 fillet, hole, chamfer 목록.
  • load path 영향 가능성.
  • local stress 해석 보류 여부.
Deliverable 2

Mesh Quality Report

전체 품질 요약과 critical zone의 worst quality 위치를 함께 둡니다.

  • element count와 element type.
  • aspect, skew, warpage, jacobian worst list.
  • stress hot spot과 quality issue의 겹침 여부.
Deliverable 3

Abaqus Handoff Checklist

solver profile export 후 Abaqus에서 읽을 evidence를 정리합니다.

  • material, section, property 이름.
  • nset, elset, surface, contact pair.
  • load, BC, connector mapping.
Deliverable 4

Mesh Sensitivity Decision Note

mesh를 조이면 수렴하는 결과와 계속 움직이는 결과를 분리합니다.

  • U, RF, Mises, Max Principal trend.
  • peak stress와 averaged hot spot 분리.
  • 현재 mesh로 판단 가능한 범위.
Evidence Checklist
Model Build

구성 확인

  • geometry cleanup이 관심 load path를 바꾸지 않는가?
  • shell/solid/beam idealization 선택 이유가 결과 목적과 맞는가?
  • connector가 실제 연결 stiffness를 과도하게 단순화하지 않는가?
Mesh Quality

품질 확인

  • worst element가 critical hot spot과 겹치는가?
  • free edge와 duplicate element가 의도된 상태인가?
  • mesh refinement trend가 판단에 충분한가?
Handoff

deck 확인

  • Abaqus input deck에서 material, section, set, surface가 추적되는가?
  • load/BC/contact 이름이 모델 의도를 설명하는가?
  • datacheck 또는 최소 input scan 결과가 남아 있는가?
